# Design: memory first, current evidence second

**Goal and architecture.** Recall preserves what a user previously asked and learned, then researches what changed without rewriting the past. TypeScript and Next.js supply the interface, Route Handlers and Node development entrypoint. vinext builds the same application for Cloudflare Workers at https://minimi-chat-agent.krishang.dev; Neon PostgreSQL persists conversations through its HTTP driver. No separate backend or persistent connection pool is needed.

**Request flow and memory.** A handler validates a bounded body, timezone and visitor session, then acquires an atomic database lease. Before saving the question, the agent retrieves recent messages and relevant prior question/answer pairs. Explicit dates are resolved in the user's timezone; otherwise PostgreSQL full-text search finds topic matches across that visitor's conversations. Missing dated history is reported rather than invented. Every data query is owner-scoped.

**Model and one tool.** OpenAI Responses uses only `gpt-6-luna`, `store:false`, streamed text and encrypted reasoning continuation. Its sole callable function is `web_search`, backed by Firecrawl search and extraction. Freshness requests force search and bypass cached page data. Independent queries run concurrently within bounded batches. Three model rounds, six deduplicated queries, bounded excerpts and deadlines limit work. Public model calls have no retries, a 48,000-character serialized input ceiling and a 1,500-output-token limit. Research failures are disclosed.

**Provenance.** Neon stores timestamps, messages and JSONB source snapshots. Historical evidence receives `H` labels; fresh evidence receives `S` labels, even when URLs match. Unknown citations are marked unverified; only cited sources persist with the final answer. Retrieved content is evidence, never instructions. Streamed text is provisional until the final saved, validated response replaces it.

**Public access and safeguards.** The shipped custom domain needs no login. Each browser gets a signed, 30-day HttpOnly/Secure/SameSite visitor cookie; it never shares an owner ID with another visitor or prior Access users. Writes require the configured canonical origin. Missing configuration fails closed. Parameterized SQL, safe links, disabled remote Markdown images and cancellation reduce exposure. Secrets stay in Worker bindings. Atomic Neon counters cap chats at 6/visitor/day, 30 globally/day and 300 globally lifetime, with separate model/search/API limits charged before work. These are usage limits, not a dollar or infrastructure-billing guarantee. Preview URLs remain disabled; the alternate workers.dev hostname retains owner-only Access.

**Interface and alternatives.** Editable, unboxed suggested prompts become personal using recent owned questions, with sensitive-pattern filtering and no provider call or profile. Self-hosted IBM Plex Sans and Light/Dark/System themes avoid external font dependencies. Hono would duplicate routing; SQLite would not persist reliably across Workers; embeddings would add indexing and cost. Inspectable full-text recall and a small bounded agent loop fit the challenge better than an additional agent framework or separate search/scrape tools.

**Verified and next steps.** TypeScript, 70 tests and the Workers build pass. Live hosted verification exercised Luna, Firecrawl, streaming and Neon persistence, plus cross-visitor denial and cross-origin rejection; concurrent database tests verified quota ceilings. Limitations remain: lexical recall misses paraphrases, date rules and context are bounded, citations do not prove correctness, cookie loss/expiry loses access to anonymous history, and shared quotas can be exhausted. Next: account recovery, currency-aware budgets, infrastructure abuse controls, richer timing/token telemetry, semantic reranking/date clarification and idempotent resumable turns. This is a verified challenge demo, not a claim of comprehensive production hardening.
