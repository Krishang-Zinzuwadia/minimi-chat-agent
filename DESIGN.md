# Recall: memory first, current evidence second

**Architecture and choices.** TypeScript/Next.js shares UI and Route Handlers; vinext builds it for Cloudflare Workers at https://minimi-chat-agent.krishang.dev, while Node remains the local entrypoint. Neon HTTP provides durable PostgreSQL without persistent pools. JSONB preserves evidence snapshots; full-text search supports inspectable recall. Hono would duplicate routing, SQLite would not persist across Workers, and embeddings would add indexing/cost. A small explicit agent loop is easier to inspect than another agent framework.

**Memory and request flow.** Validate body, timezone, origin and signed visitor; acquire an atomic PostgreSQL lease; retrieve recent messages and relevant prior question/answer pairs before saving the question. Resolve explicit dates in the user's timezone; otherwise use owner-scoped full-text search across conversations. Missing dated history is reported, never fabricated. Token-scoped leases prevent overlapping turns and stale releases.

**AI, tool and provenance.** OpenAI Responses uses only GPT-6 Luna, `store:false`, SSE streaming and encrypted reasoning continuation. One callable `web_search` tool uses Firecrawl search/extraction; freshness requests force search and bypass cached pages. Independent queries run concurrently in bounded batches. Timestamped historical evidence gets H labels and fresh evidence S labels, including when URLs match. Unknown citations are marked unverified; only cited sources persist with the final answer. Retrieved text is untrusted evidence. Streaming remains provisional until the validated, saved final event; failed research is disclosed.

**UI decisions.** React, Tailwind, Radix Dialog, Motion and Markdown/GFM support a responsive research workspace. Editable, unboxed prompt suggestions feed the composer without auto-sending; conversation search and on-demand source/history panels keep evidence available without crowding the answer. Suggestions use at most 40 owned questions with conservative sensitive-pattern filtering, no provider call or inferred profile. Self-hosted IBM Plex Sans avoids external font requests. Light/Dark/System themes use a validated first-party preference cookie and CSS system preference for consistent initial rendering; contrast assertions cover text, errors and focus.

**Public identity and safety.** No login is required on the custom domain. Signed 30-day HttpOnly/Secure/SameSite visitor cookies isolate each browser from other visitors and previous Access users. Every query is owner-scoped; writes require the canonical origin. Missing configuration fails closed. Parameterized SQL, safe links, disabled remote Markdown images and cancellation reduce exposure. Secrets stay in Worker bindings. Preview URLs are disabled; the alternate workers.dev hostname retains owner-only Access.

**Limits and trade-offs.** A turn accepts 4,000 question characters, runs at most three model rounds/six deduplicated search queries, and has a 90-second deadline. Public model calls allow 48,000 serialized input characters, 1,500 output tokens and no retries. Atomic Neon admission caps, charged before work, are: globally API 3,000/day and 30,000 lifetime; chats 30/day and 300 lifetime; model and search each 60/day and 600 lifetime. Per visitor: API 120/day, chats 6/day, each provider 12/day; lifetime ceilings are 30 times each daily limit. One active turn per owner; failed/cancelled attempts count. Daily resets use UTC; lifetime counters do not reset on redeploy. Cookie replacement cannot bypass global caps. Shared quotas can be exhausted and do not cap dollar or infrastructure bills. Cookie loss/expiry loses anonymous history access; lexical recall, date rules and context are bounded; citations do not guarantee truth.

**Evidence and next steps.** TypeScript, 70 automated tests and the Workers build pass. Tests cover temporal/DST retrieval, SQL isolation/leases, provider/SSE handling, citations, suggestions/contrast, signed sessions, origin rejection and quotas. Live checks verified Luna/Firecrawl streaming, Neon persistence, cross-visitor denial, cross-origin blocking and concurrent quota ceilings. Browser inspection verified public UI readiness; discovering 36 Playwright cases is not proof they all ran. Next: account recovery, currency-aware budgets/infrastructure abuse controls, richer telemetry, semantic reranking/date clarification and idempotent resumable turns. This is a verified challenge demo, not comprehensive production hardening.
